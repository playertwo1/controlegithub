# C09.2 — Marcar notificações lidas: Evidência de Conclusão

**Estado:** `CONCLUÍDO` — Critérios de aceite 1–5 comprovados empiricamente em testes unitários, lint e testes instrumentados no emulador Pixel 9 (API 37). Validação de mutação real contra a API do GitHub registrada como `NOT_RUN` conforme o Gate de Notificações (exige autorização humana prévia do alvo específico e sessão ativa no emulador).

**Ambiente:** Windows, Pixel 9 AVD / API 37 (`emulator-5554`), JDK 17, Gradle 9.3.1.

## Implementação

- **Transporte HTTP (`GitHubHttpClient.kt`):**
  - Adicionado método `patch(path: String, accessToken: String?): GitHubHttpCall`.
  - Configuração do método `PATCH` com `doOutput = true`, `setFixedLengthStreamingMode(0)` e fechamento de `outputStream` para envio de corpo vazio (`Content-Length: 0`), conforme RFC 5789 e REST API do GitHub.
  - Suporte aos códigos `205 Reset Content` e `304 Not Modified` como sucessos (`GitHubHttpResult.Success`) com corpo vazio.
  - Fallback por reflexão via `setRequestMethod` para permitir execução de `PATCH` no `HttpURLConnection` padrão da JVM do host durante testes unitários locais, com flag `--add-opens=java.base/java.net=ALL-UNNAMED` configurada em `app/build.gradle.kts`. No Android (ART), o OkHttp subjacente suporta PATCH nativamente.
- **Domínio (`GitHubNotifications.kt`):**
  - Implementada função `markNotificationAsRead(client, accessToken, threadId): MarkNotificationReadResult`.
  - Validação estrita de formato do `threadId` com regex `^[A-Za-z0-9_-]+$`, prevenindo manipulação de caminho ou injeção.
  - Mapeamento de erros HTTP (`401 Unauthorized`, `403 Forbidden`, `404 Not Found`, `429 Rate Limited`, `500 Server Error` e `Network`).
- **Interface e Estado (`GitHubNotificationsScreen.kt`):**
  - Estados `markingReadId` e `markReadError` gerenciados no ciclo da tela.
  - Botão "Marcar como lida" com tag semântica `notification-mark-read` no `NotificationDetail`, exibido exclusivamente para notificações não lidas (`unread == true`).
  - Durante o envio, o botão é desabilitado e exibe um `CircularProgressIndicator`, prevenindo toques repetidos ou requisições concorrentes duplicadas.
  - Em resposta 205 ou 304, o estado da notificação no detalhe e na coleção `notifications` é atualizado para `unread = false`, o botão de marcar desaparece e o card exibe o status "Lida".
  - Com o filtro "Não lidas" ativo, ao retornar à lista, o item lido é imediatamente omitido da visualização filtrada sem perda de paginação.
  - Em falha (rede ou status HTTP de erro), o estado `unread = true` é preservado, o erro correspondente é exibido e o botão é reabilitado para nova tentativa.
  - Em `401 Unauthorized`, a expiração de sessão é repassada para `onSessionExpired` sem marcar localmente como lida.

### Detalhamento dos Testes Instrumentados em C09.2

1. `markingNotificationAsReadSendsPatchAndUpdatesLocalStateToRead`: Valida envio de `PATCH /notifications/threads/thread-1`, recebimento de `205 Reset Content`, atualização local para "Lida · Atribuída a você", desaparecimento do botão "Marcar como lida" e remoção automática da lista sob o filtro "Não lidas".
2. `markingNotificationAsReadWith304UpdatesLocalStateToRead`: Valida resposta `304 Not Modified`, atualizando o estado para lida com desaparecimento do botão de ação.
3. `markingNotificationAsReadFailurePreservesUnreadAndDisplaysErrorMessage`: Valida erro de servidor (500), preservação do status "Não lida", renderização de mensagem de erro ao usuário e manutenção do botão ativo para retentativa.
4. `markingNotificationAsReadWith401PreservesUnreadAndNotifiesSessionExpiry`: Valida resposta `401 Unauthorized`, acionando `onSessionExpired` e mantendo a notificação não lida.
5. Demais testes de tela e domínio (9 testes de filtros, origens, deduplicação e parsing de C09.1 mantidos em conformidade).

## Auditoria Independente

Auditoria independente realizada via subagente com base no contrato `plan/contracts/C09.2.md`, evidências e código-fonte.
- **Veredito:** **PASS** (Aprovado sem ressalvas impeditivas).
- **Critério 1:** CONFORME — `markNotificationAsRead` processa 205 e 304 como `Success`. `selectedNotification` e `notifications` são atualizados para `unread = false`. O botão de ação é condicionado a `notification.unread`, deixando de ser renderizado, e o card/detalhe exibe "Lida". Validado pelos testes `markingNotificationAsReadSendsPatchAndUpdatesLocalStateToRead` e `markingNotificationAsReadWith304UpdatesLocalStateToRead`.
- **Critério 2:** CONFORME — Dupla proteção implementada: guard `if (markingReadId == null)` na corrotina e desativação do botão `enabled = !markingRead` com exibição de `CircularProgressIndicator` de 16.dp durante o envio.
- **Critério 3:** CONFORME — Em `MarkNotificationReadResult.Failure`, `notifications` e `selectedNotification` mantêm `unread = true`. A mensagem localizada de `GitHubHttpError` é exibida em `markReadError` com cor de erro e o botão é reabilitado para retentativa. Validado em `markingNotificationAsReadFailurePreservesUnreadAndDisplaysErrorMessage`.
- **Critério 4:** CONFORME — Status 401 gera `GitHubHttpError.UNAUTHORIZED`, invocando `onSessionExpired(session)` e mantendo `unread = true`. Validado em `markingNotificationAsReadWith401PreservesUnreadAndNotifiesSessionExpiry`.
- **Critério 5:** CONFORME — O filtro `readFilter == NotificationReadFilter.UNREAD` avalia `notification.unread`. Como o item na lista `notifications` tem `unread = false`, ele é excluído da projeção filtrada imediatamente, preservando a coleção base e o controle `hasNext`/`pager`. Validado em teste instrumentado de tela.
- **Segurança e Regras:** Validação estrita de `threadId` com regex `^[A-Za-z0-9_-]{1,80}$`; transporte HTTP nativo via `HttpURLConnection` com PATCH, `setFixedLengthStreamingMode(0)` e fallback por reflexão seguro na JVM do host; ausência de vazamento de credenciais em logs; conformidade com o Gate de Notificações (mutação real mantida como `NOT_RUN` sem alvos pré-autorizados pelo usuário).
