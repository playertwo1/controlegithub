## Implementação

- **Suporte a PATCH com payload JSON no Cliente HTTP (`GitHubHttpClient.kt`):**
  - O método `patch(path: String, accessToken: String? = null, jsonBody: String? = null): GitHubHttpCall` foi atualizado para suportar envio de corpo JSON serializado.
  - Quando `jsonBody` está presente, configura `doOutput = true`, cabeçalho `Content-Type: application/json; charset=utf-8` e `setFixedLengthStreamingMode` para transmissão eficiente em fluxo sem buffering redundante.
  - Testado unitariamente com mock server local em `patchSendsJsonBodyAndReceives200Ok`.
- **Camada de Domínio e Validações Seguras (`GitHubIssueDetail.kt`):**
  - Implementada função `createIssueComment(client, accessToken, repository, issueNumber, body, isOffline)` retornando `CreateIssueCommentResult`:
    - `Success(val comment: GitHubIssueComment)`
    - `Failure(val error: GitHubHttpError, val statusCode: Int? = null)`
    - `EmptyBody`
    - `Offline`
  - Implementada função `editGitHubIssue(client, accessToken, currentIssue, title, body, isOffline)` retornando `EditIssueResult`:
    - `Success(val detail: GitHubIssueDetail)`
    - `Failure(val error: GitHubHttpError, val statusCode: Int? = null)`
    - `EmptyTitle`
    - `Offline`
  - Sanitização de caracteres JSON com `escapeJson` puro Kotlin sem dependências externas.
  - Analisador `parseCreatedIssueComment` para decodificar a resposta `201 Created` do GitHub para a entidade de domínio `GitHubIssueComment`.
- **Interface de Detalhes da Issue (`GitHubIssueDetailScreen.kt`):**
  - Interface desenvolvida em Jetpack Compose com UI 100% em português brasileiro.
  - **COMMENT-01 (Envio de comentário com sucesso):** Campo de texto para comentário, validação local, disparo de `POST /repos/{owner}/{repo}/issues/{number}/comments`, inclusão imediata do novo comentário na lista e limpeza do campo de texto.
  - **COMMENT-02 (Anti-duplo clique no comentário):** Desativação instantânea do botão "Comentar" no primeiro clique com exibição de `CircularProgressIndicator` e texto "Enviando...", prevenindo comentários duplicados.
  - **COMMENT-03 (Preservação de rascunho de comentário):** Em caso de falha de conexão, timeout ou erro 403/500, o texto redigido permanece intacto no campo (`newCommentText`) e uma mensagem clara de erro é exibida.
  - **EDIT-01 (Edição de título e descrição da issue):** Modo de edição acessível pelo botão "Editar", permitindo alterar título e corpo; submissão via `PATCH /repos/{owner}/{repo}/issues/{number}`; atualização instantânea do cabeçalho da issue na tela com resposta `200 OK`.
  - **MUTATION-GUARD (Validação local e bloqueio offline):** Comentário vazio ou título vazio na edição são bloqueados antes de qualquer chamada de rede com mensagens descritivas; quando em modo offline (`isOffline = true`), botões de mutação são desabilitados/ocultados e um banner vermelho informativo é apresentado.

1. **`GitHubHttpClientTest` (1 teste unitário JVM adicionado):**

2. **`EditAndCommentIssueTest` (6 testes unitários JVM):**
   - `createIssueCommentEmptyBodyReturnsEmptyBodyWithoutNetwork`: Valida bloqueio de comentário vazio sem chamada de rede.
   - `createIssueCommentOfflineReturnsOfflineWithoutNetwork`: Valida rejeição instantânea quando `isOffline = true`.
   - `createIssueCommentForbiddenMapsToFailure`: Valida mapeamento de HTTP 403.
   - `editGitHubIssueEmptyTitleReturnsEmptyTitleWithoutNetwork`: Valida bloqueio de edição com título vazio.
   - `editGitHubIssueOfflineReturnsOfflineWithoutNetwork`: Valida bloqueio de edição offline.
   - `editGitHubIssueForbiddenMapsToFailure`: Valida mapeamento de erro 403 na edição.
3. **`EditAndCommentIssueAndroidTest` (2 testes instrumentados ART):**
   - `parseCreatedIssueCommentMapsFieldsCorrectly`: Valida decodificação de JSON de comentário criado (`id`, `body`, `user`, `created_at`).
   - `parseCreatedIssueCommentRejectsMissingBody`: Valida rejeição de resposta sem corpo de comentário.
4. **`EditAndCommentIssueUiTest` (7 testes instrumentados Compose no Pixel 9):**
   - `commentSuccessSubmitsPostAppendsToUiAndClearsInput`: Valida envio de comentário (201 Created), inserção na lista e limpeza do campo de texto (COMMENT-01).
   - `commentAntiDoubleTapDisablesButtonDuringSubmission`: Valida desativação do botão e spinner durante o envio, sem disparo duplo (COMMENT-02).
   - `commentFailurePreservesDraftTextAndDisplaysError`: Valida exibição de erro descritivo e preservação integral do texto em caso de falha 403 (COMMENT-03).
   - `editIssueSuccessSubmitsPatchAndUpdatesHeader`: Valida fluxo de edição com envio de PATCH (200 OK) e atualização do título na tela (EDIT-01).
   - `editIssueFailurePreservesDraftAndDisplaysError`: Valida mensagem de erro e retenção das alterações digitadas em caso de falha 403 (EDIT-01 / COMMENT-03).
   - `mutationGuardEmptyValidation`: Valida mensagens de erro locais para comentário em branco e título em branco sem requisições de rede (MUTATION-GUARD).
   - `mutationGuardOfflineBlocked`: Valida banner informativo offline e ausência de campos/botões de mutação quando offline (MUTATION-GUARD).
