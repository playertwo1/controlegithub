## Implementação

- **Camada de Domínio e Modelo de Dados (`GitHubIssueDetail.kt`):**
  - Implementado analisador `parseIssueDetailAssignees` para decodificar a lista de responsáveis da issue devolvida pela API do GitHub (`assignees: [{"login": "..."}]`).
  - Atualizada a função `parseGitHubIssueDetail` para mapear tanto `labels` quanto `assignees` atualizados para a entidade de domínio `GitHubIssue`.
  - Implementada função `updateIssueState(client, accessToken, currentIssue, newState, isOffline)` retornando `MutateIssueStateResult`:
    - `Success(val detail: GitHubIssueDetail)`
    - `Failure(val error: GitHubHttpError, val statusCode: Int? = null)`
    - `Offline`
  - Atualizada a função `editGitHubIssue` para suportar atualização simultânea de metadados (`labels: List<String>?`, `assignees: List<String>?`), serializando arrays JSON sem dependências externas.
- **Interface e Interações (`GitHubIssueDetailScreen.kt`):**
  - Desenvolvida em Jetpack Compose com UI 100% em português brasileiro.
  - **STATE-01 (Fechar issue aberta):** Quando a issue está aberta (`OPEN`), exibe botão "Fechar issue" (`issue_close_button`). Ao clicar, envia `PATCH /repos/{owner}/{repo}/issues/{number}` com `{"state":"closed"}`. No retorno `200 OK`, o estado da issue na tela é atualizado para "Fechada" e o botão passa a ser "Reabrir issue".
  - **STATE-02 (Reabrir issue fechada):** Quando a issue está fechada (`CLOSED`), exibe botão "Reabrir issue" (`issue_reopen_button`). Ao clicar, envia `PATCH` com `{"state":"open"}`. No retorno `200 OK`, a issue passa para "Aberta" e o botão se torna "Fechar issue".
  - **METADATA-01 (Gerenciamento de rótulos e responsáveis):** Na visualização, exibe os responsáveis atuais (`issue_assignees_text`) e rótulos (`issue_labels_text`). No formulário de edição, disponibiliza campos para rótulos (`issue_edit_labels_input`) e responsáveis (`issue_edit_assignees_input`). A submissão envia os novos arrays no `PATCH`, atualizando a tela imediatamente no retorno `200 OK`.
  - **PERMISSION-01 (Tratamento de erro 403 Forbidden):** Em caso de permissão negada, exibe mensagem clara ("Você não tem permissão para alterar o estado desta issue.") e preserva o estado e metadados anteriores intactos.
  - **MUTATION-GUARD (Anti-duplo clique e modo offline):** Todos os botões de ação são desabilitados com indicador de progresso durante o envio da mutação, impedindo requisições concorrentes ou duplicadas. Em modo offline (`isOffline = true`), botões de mutação são ocultados e o banner informativo é apresentado (sem fila de mutações offline).

### Detalhamento dos Testes de C12.3

1. **`IssueMetadataAndStateTest` (6 testes unitários JVM):**
   - `updateIssueStateOpenToClosedSendsPatchStateClosed`: Valida envio de `PATCH` com payload `{"state":"closed"}` e cabeçalho `Authorization: Bearer <token>`.
   - `updateIssueStateClosedToOpenSendsPatchStateOpen`: Valida envio de `PATCH` com payload `{"state":"open"}`.
   - `updateIssueStateOfflineReturnsOfflineWithoutNetwork`: Valida que o modo offline bloqueia a chamada sem emitir tráfego de rede.
   - `updateIssueStateForbiddenReturnsFailure`: Valida mapeamento do status HTTP 403 para falha com `GitHubHttpError.FORBIDDEN`.
   - `editGitHubIssueWithLabelsAndAssigneesSerializesJsonArrays`: Valida serialização segura de arrays JSON de `labels` e `assignees`.
   - `editGitHubIssueEmptyTitleReturnsEmptyTitleWithoutNetwork`: Valida rejeição local de título vazio na edição.
2. **`IssueMetadataAndStateAndroidTest` (2 testes instrumentados ART):**
   - `parseGitHubIssueDetailMapsAssigneesAndLabelsCorrectly`: Valida decodificação de JSON completo com `labels` e `assignees` para a entidade `GitHubIssue`.
   - `parseGitHubIssueDetailHandlesEmptyAssigneesAndLabels`: Valida robustez de parsing quando listas de metadados vêm vazias ou ausentes.
3. **`IssueMetadataAndStateUiTest` (6 testes instrumentados Compose no Pixel 9):**
   - `closeIssueSuccessSendsPatchAndUpdatesUiToClosed`: Comprova que fechar issue envia PATCH `{"state":"closed"}`, atualiza o cabeçalho para "Fechada" e altera o botão para "Reabrir issue" (STATE-01).
   - `reopenIssueSuccessSendsPatchAndUpdatesUiToOpen`: Comprova que reabrir issue envia PATCH `{"state":"open"}`, atualiza o cabeçalho para "Aberta" e altera o botão para "Fechar issue" (STATE-02).
   - `editIssueMetadataUpdatesLabelsAndAssignees`: Comprova edição e persistência de rótulos e responsáveis (METADATA-01).
   - `permissionForbidden403DisplaysErrorAndPreservesState`: Comprova que erro 403 Forbidden exibe mensagem amigável e preserva o estado local (PERMISSION-01).
   - `mutationGuardAntiDoubleTapDisablesButtonDuringStateChange`: Comprova que toques repetidos durante o envio não geram múltiplas requisições (MUTATION-GUARD).
   - `mutationGuardOfflineHidesMutationButtons`: Comprova que no modo offline os botões de mutação são ocultados (MUTATION-GUARD).
