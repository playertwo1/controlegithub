## Implementação

- **Camada de Domínio e Modelo de Dados (`GitHubPullRequests.kt`):**
  - Implementado enum `PullRequestReviewEvent`:
    - `APPROVE("APPROVE", "Aprovar")`
    - `REQUEST_CHANGES("REQUEST_CHANGES", "Solicitar alterações")`
    - `COMMENT("COMMENT", "Comentar revisão")`
  - Implementado tipo selado `SubmitPullRequestReviewResult`:
    - `Success(val review: GitHubPullRequestReview)`
    - `Failure(val error: GitHubHttpError, val statusCode: Int? = null)`
    - `EmptyChangesBody`
    - `SelfReviewForbidden`
    - `Offline`
  - Implementado analisador `parseCreatedPullRequestReview` decodificando a resposta do review criado (`id`, `user.login`, `state`, `body`, `submitted_at`).
  - Implementada função `submitPullRequestReview(client, accessToken, repository, pullNumber, event, body, commitId, isOffline)`:
    - Validação local de justificativa vazia para `REQUEST_CHANGES` retornando `EmptyChangesBody` sem requisição de rede.
    - Validação de modo offline retornando `Offline` sem tráfego HTTP.
    - Rota REST autenticada: `POST /repos/{owner}/{repo}/pulls/{pull_number}/reviews`.
    - Payload JSON com `event`, `body` (sanitizado com `escapeJson`) e `commit_id` opcional.
    - Mapeamento de erro HTTP 422 para `SelfReviewForbidden` (autor tentando aprovar ou solicitar alterações no próprio PR).
- **Interface e Interações (`GitHubPullRequestsScreen.kt`):**
  - Desenvolvida em Jetpack Compose com UI 100% em português brasileiro.
  - **REVIEW-APPROVE (Aprovação de Pull Request com sucesso):** Seleção do parecer "Aprovar" (`pr_review_event_approve`), preenchimento opcional de parecer (`pr_review_input`) e submissão via `pr_review_submit_button`. Ao retornar `200 OK`, a nova revisão ("Aprovou · @login") é anexada à lista de reviews e o campo é limpo.
  - **REVIEW-CHANGES (Solicitação de alterações com justificativa obrigatória):** Seleção de "Solicitar alterações" (`pr_review_event_request_changes`). Tentativa com texto vazio é barrada localmente ("É obrigatório justificar as alterações solicitadas."). Quando preenchida e aceita, adiciona à lista com estado "Solicitou alterações".
  - **REVIEW-SELF (Tratamento de auto-revisão):** Se o usuário autenticado for o próprio autor do PR, um aviso prévio informativo é exibido (`pr_review_author_warning`). Caso tente aprovar ou solicitar alterações, uma mensagem explicativa clara é exibida ("Você não pode aprovar ou solicitar alterações no seu próprio pull request.") e o rascunho digitado é preservado intacto.
  - **REVIEW-ANTI-DOUBLE-TAP (Proteção contra toques repetidos):** Botão de envio desabilitado síncronamente no primeiro clique com exibição de `CircularProgressIndicator` (`pr_review_progress`), e bloqueio conjunto de navegação e botões superiores.
  - **MUTATION-GUARD (Preservação de rascunho em falha e bloqueio offline):** Em falhas de rede, 403 Forbidden ou 5xx, o texto digitado permanece preservado e o erro é exibido (`pr_review_error`). Em modo offline, o formulário é substituído por `pr_review_offline_banner` ("Modo offline: Conexão necessária para enviar revisões de pull request.") sem fila de escrita offline.

   - `submitPullRequestReviewOfflineReturnsOfflineWithoutNetworkCall`: Valida bloqueio imediato no modo offline sem tráfego HTTP.
   - `submitPullRequestReviewInvalidRepoOrNumberReturnsFailureWithoutNetworkCall`: Valida rota e parâmetros de repositório/PR.
   - `submitPullRequestReviewForbiddenReturnsFailureAndSendsPost`: Valida envio de `POST` com cabeçalhos e payload JSON corretos (`event`, `body`, `commit_id`) e mapeamento de erro HTTP 403.
   - `submitPullRequestReviewSelfReviewReturnsSelfReviewForbidden`: Valida mapeamento do erro HTTP 422 para `SelfReviewForbidden`.
2. **`SubmitPullRequestReviewAndroidTest` (2 testes instrumentados ART):**
