## Implementação

- Tocar uma linha da lista real abre detalhe para o mesmo owner/nome e confere
  também id e `full_name` devolvidos pelos metadados.
- Exibe descrição, visibilidade, branch padrão, estrelas, forks, total de issues
  e PRs abertas (`open_issues_count`) e data/hora do último push (`pushed_at`).
  Campo indisponível não vira zero; zero explícito continua visível.
- Busca README na branch padrão, decodifica Base64/UTF-8 e mostra o Markdown
  como texto inerte. Links, tags, imagens e blocos de código não executam nem
  abrem navegador.
- README `404` mantém o restante do detalhe. Atualizar busca os dados novamente;
  voltar mantém busca/filtro e não refaz a lista.

### Reproduzir a inspeção Maestro

1. Execute `./gradlew.bat connectedDebugAndroidTest '-Pandroid.testInstrumentationRunnerArguments.class=com.playertwo.controlegithub.GitHubRepositoryDetailScreenTest#opensRealSelectionShowsInertReadmeRefreshesAndReturnsWithSearch' '-Pandroid.testInstrumentationRunnerArguments.maestroPreview=true' --console=plain`.
2. Durante a pausa opt-in de 60 s, use `mcp__maestro__list_devices`, depois
   `mcp__maestro__inspect_screen({device_id: "emulator-5554"})` e
   `mcp__maestro__take_screenshot({device_id: "emulator-5554"})`.

A captura de teste fica escurecida pela activity instrumentada. Ela registra
hierarquia, campos e conteúdo inerte da fixture; não substitui avaliação de
contraste em produção.
