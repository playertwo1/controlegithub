### Falha de fixture HTTP no teste SAF API 28

- Causa: o AVD API 28 executa o teste contra uma fixture HTTP em `127.0.0.1`, enquanto cleartext fica desativado por padrão a partir do Android 9 para apps que miram API 28 ou superior. O Android 17 tem uma exceção implícita para localhost quando nenhuma configuração foi definida, por isso o problema não aparecia no Pixel_9. [Configuração oficial de segurança de rede](https://developer.android.com/privacy-and-security/security-config).
- Correção: a configuração de segurança foi anexada somente ao manifesto `debug` e permite HTTP apenas para `127.0.0.1` (`includeSubdomains=false`). O manifesto mesclado de `release` foi reprocessado após essa alteração e não contém `networkSecurityConfig` nem `usesCleartextTraffic=true`; [snapshot](artifacts/C21.2-connected-after-api28-final-20261021/release-merged-AndroidManifest.xml) e [log da mesclagem](C21.2-release-manifest-after-api28-20261021.log) arquivados. A política de produção não foi ampliada.
- Resultado: o fluxo de abertura/cancelamento SAF passou 1/1 em API 28 e a suíte conectada final passou 204/204 em API 37. O teste API 28 confirma cancelamento e retorno ao app; seleção real, criação de arquivo por SAF e validação física seguem pendentes.

### Investigação do `MutableIntervalList`

- Os rastros falham em `LazyLayoutIntervalContent.getKey` durante a medição, pedindo o índice 4 quando a lista tem tamanho 4. Houve ocorrências no filtro de favoritos, no estado de instalação da release e, mais recentemente, durante a paginação de Actions. O XML não identifica uma causa de aplicação; os três testes passaram quando repetidos isoladamente, e a última suíte integral passou.
- A configuração resolvida é Compose Foundation 1.7.6, alinhada ao BOM 2024.12.01. Nas duas telas, `items()` recebe listas derivadas (`visibleRepositories` e `sortedAssets`) e chaves estáveis por ID; a revisão não encontrou mutação in-place dessas listas. A tela de favoritos e seu teste estão sem alterações locais neste checkout. O estado observado pelo WorkManager altera os controles de cada asset, sem alterar a quantidade de assets.
- O [Issue Tracker 300504058](https://issuetracker.google.com/issues/300504058) contém um rastro semelhante, mas foi encerrado como “Can't Repro”; o comentário que relaciona um caso conhecido a outro bug exige `performLookaheadMeasure`, ausente nos rastros desta suíte. As notas oficiais do [Compose Foundation](https://developer.android.com/jetpack/androidx/releases/compose-foundation) não registram correção correspondente nas versões 1.7.7 ou 1.7.8.
- Hipótese atual: falha intermitente no ciclo de medição/atualização de uma lista lazy, ainda sem vínculo confirmado com código do app ou com uma correção específica do Compose. Nesta etapa da investigação não alterei código nem dependências; a atualização anterior do BOM para 2024.12.01 permanece. O PASS integral mais recente comprova esta execução, mas não estabelece a causa nem garante que a intermitência foi eliminada.
