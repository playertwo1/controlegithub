# C26.1 — Issues e Pull Requests por repositório e refinamento do ícone

## Escopo

- Em `GitHubRepositoryDetailScreen`, disponibilizar a ação **"Issues e PRs"** (`repository_work_button`) para abrir a tela de demandas específicas do repositório (`GitHubRepositoryWorkScreen`).
- Em `GitHubRepositoryWorkScreen`, permitir alternar entre **Issues** e **Pull requests** daquele `owner/repo`, filtrar por estado (`Abertas`, `Fechadas`, `Todas`), paginar resultados da API REST do GitHub, acionar **"Nova issue"** e abrir o detalhe existente de qualquer issue (`GitHubIssueDetailScreen`) ou pull request (`GitHubPullRequestDetailScreen`) com retorno previsível preservando filtros e lista carregada.
- Em `GitHubIssues.kt`, suportar `fallbackRepository: String? = null` em `parseGitHubIssues` e adicionar `githubRepositoryIssuesPath` + `GitHubRepositoryIssuePager` para `GET /repos/{owner}/{repo}/issues?state={open|closed|all}&per_page=50`, descartando itens que contenham `"pull_request"`.
- Em `GitHubPullRequests.kt`, adicionar `GitHubRepositoryPullRequestState` (`OPEN`, `CLOSED`, `ALL`), `githubRepositoryPullRequestsPath`, `parseGitHubRepositoryPullRequests` e `GitHubRepositoryPullRequestPager` para `GET /repos/{owner}/{repo}/pulls?state={open|closed|all}&per_page=50`.
- Refinar os vetores do ícone adaptativo (`@drawable/ic_launcher_foreground`, `@drawable/ic_launcher_background`, `@drawable/ic_launcher`) com a identidade **Cyber Octocat & Git** (silhueta Octocat estilizada integrada ao grafo Git luminoso).
- Fora de escopo: criar novos escopos OAuth, alterar a aba geral `Demandas` fora do repositório ou tocar em `C21.3`.

## Pré-condições e decisões

- `C07.2`, `C08.1`, `C12.1`, `C13.1` e `C25.2` estão `DONE`.
- Resolve a questão aberta #1 de `plan/contracts/C25.1.md`, completando o fluxo de acessar todas as demandas (Issues e PRs) diretamente a partir do repositório aberto (seja pela aba Repositórios ou pelos atalhos de Avisos).
- O endpoint `/repos/{owner}/{repo}/issues` da API do GitHub não inclui o objeto aninhado `"repository"` em cada item e mistura pull requests na resposta; portanto, o parser deve aceitar o `owner/repo` validado do repositório como fallback e continuar ignorando itens com `"pull_request"`.

## Aceite

1. Dado um repositório carregado em `GitHubRepositoryDetailScreen`, quando toco em **"Issues e PRs"**, então vejo a tela `GitHubRepositoryWorkScreen` do `owner/repo` selecionado com abas **"Issues"** e **"Pull requests"** e filtros de estado (**"Abertas"**, **"Fechadas"**, **"Todas"**).
2. Dada a aba **"Issues"** de um repositório, quando os dados carregam de `/repos/{owner}/{repo}/issues`, então apenas issues reais daquele repositório são exibidas (sem pull requests infiltrados), e tocar em uma issue abre `GitHubIssueDetailScreen` com retorno à lista do repositório.
3. Dada a aba **"Pull requests"** de um repositório, quando os dados carregam de `/repos/{owner}/{repo}/pulls`, então os PRs do repositório exibem estado (`Aberto`, `Fechado` ou `Mesclado`), autor e número, e tocar em um PR abre `GitHubPullRequestDetailScreen` com retorno à lista do repositório.
4. Dado erro de rede, acesso negado ou lista vazia nas Issues/PRs do repositório, então a tela exibe estado vazio ou erro explícito com opção de tentar novamente, sem dados de demonstração.
5. Dado os recursos de ícone do aplicativo, quando `assembleDebug` e `lintDebug` executam, então o Adaptive Icon Cyber Octocat & Git compila sem erros ou avisos bloqueantes.
