# C13.1 — Comentar PR

## Escopo

Permitir que o usuário adicione comentários de discussão a um Pull Request existente exibido na tela de detalhe (`GitHubPullRequestDetailScreen`), utilizando a rota autenticada `POST /repos/{owner}/{repo}/issues/{pull_number}/comments` da API REST do GitHub.

Comportamentos incluídos:
- Formulário de envio de comentários na seção de comentários do Pull Request com UI em português brasileiro.
- Validação local bloqueando envio de comentário em branco antes de qualquer requisição de rede.
- Proteção anti-duplo clique (anti-double-tap) com desativação síncrona imediata do botão e exibição de indicador de progresso.
- Preservação integral do rascunho digitado em caso de falha de conexão, timeout, `403 Forbidden` ou erro de servidor.
- Bloqueio imediato em modo offline com aviso informativo.

Exclusões deste contrato:
- Envio de revisões formais de Pull Request (aprovação, solicitação de mudanças e parecer de revisão) (pertence a C13.2).
- Comentários posicionais em linhas específicas do diff de código (`/pulls/{number}/comments`).
- Edição ou exclusão de comentários já postados.
- Fila de escrita offline para sincronização tardia (proibida pelas regras de segurança do projeto).

## Pré-condições e decisões

- Pré-requisitos C08.2 (Visualização de PR) e C11.2 (Refresh e reconexão) concluídos com sucesso (`DONE`).
- Acesso à API do GitHub:
  - Rota de comentários gerais de PR: `POST /repos/{owner}/{repo}/issues/{pull_number}/comments`.
  - Body: JSON com campo obrigatório `body` (string não vazia).
  - Status de sucesso: `201 Created` retornando o objeto do comentário criado (`id`, `user`, `body`, `created_at`).
  - Respostas de erro esperadas:
    - `401 Unauthorized`: Sessão expirada ou token revogado.
    - `403 Forbidden`: Usuário sem permissão de escrita ou PR trancado.
    - `404 Not Found`: Repositório ou PR inexistente.
    - `422 Unprocessable Entity`: Validação recusada pelo GitHub.
- Decisão sobre transporte HTTP (`GitHubHttpClient.kt`):
  - Utiliza o método `post(path, accessToken, jsonBody)` já implementado com streaming UTF-8 (`setFixedLengthStreamingMode`).
  - Sanitização com `escapeJson` puro Kotlin sem dependências externas.
- Decisão sobre anti-duplo clique e modo offline:
  - Desativação imediata do botão ao primeiro clique com exibição de `CircularProgressIndicator`.
  - Nenhuma tentativa de envio no modo offline (`isOffline = true`), exibindo banner de conexão necessária.

## Aceite

1. **COMMENT-01 (Envio de comentário no PR com sucesso):**
   **Dado** um usuário autenticado na tela de detalhe de um Pull Request,
   **quando** digita um comentário não vazio e aciona o botão de envio, e o servidor responde `201 Created`,
   **então** o novo comentário é adicionado à lista de comentários do PR e o campo de texto é limpo.

2. **COMMENT-02 (Anti-duplo clique no PR):**
   **Dado** que o envio de um comentário no PR está em andamento,
   **quando** o usuário toca repetidamente no botão de enviar,
   **então** novos toques são ignorados, o botão permanece desabilitado com indicador de progresso e apenas uma requisição HTTP é emitida.

3. **COMMENT-03 (Preservação de rascunho de comentário em falha):**
   **Dado** que o usuário digitou um comentário no PR,
   **quando** a requisição falha por erro de rede, timeout, `403 Forbidden` ou erro de servidor,
   **então** o texto digitado permanece no campo de comentário sem ser descartado e uma mensagem de erro clara é exibida ao usuário.

4. **MUTATION-GUARD (Validação local e bloqueio offline):**
   **Dado** que o campo de comentário está vazio/em branco ou o aplicativo está em modo offline,
   **quando** o usuário tenta submeter o comentário,
   **então** a ação é bloqueada localmente antes de qualquer chamada HTTP, exibindo a respectiva validação ou alerta de modo offline.
