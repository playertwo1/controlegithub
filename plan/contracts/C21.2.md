# C21.2 — Baixar e instalar APK de release

## Escopo

- Baixar assets `.apk` selecionados pelo usuário de releases públicas ou privadas, com progresso, cancelamento, notificação de andamento e de conclusão quando notificações estiverem autorizadas.
- Executar o download em `CoroutineWorker` de primeiro plano. O token é carregado de `SecureSessionStore` durante a execução e nunca vai para `WorkManager Data`, URL, UI, notificação ou log.
- Requisitar `GET /repos/{owner}/{repo}/releases/assets/{id}` com `Accept: application/octet-stream`. Aceitar `200` binário direto ou um `302` para URL HTTPS sem credenciais; não encaminhar `Authorization` ao destino do redirect.
- Gravar primeiro em arquivo temporário privado, calcular SHA-256 em streaming e publicar somente após a validação. Preferir `digest` SHA-256 da API; quando ausente, usar a entrada do APK no asset `SHA256SUMS` da mesma release. Se não existir uma fonte de hash, informar que o arquivo não foi verificado. Em divergência, apagar o arquivo e bloquear instalação.
- Em API 29+, publicar em `MediaStore.Downloads/Download`. Em API 26–28, usar `ACTION_CREATE_DOCUMENT`, sugerir a pasta Downloads quando disponível e respeitar o destino escolhido. Não solicitar permissão ampla de armazenamento.
- Instalar apenas por ação explícita do usuário, com URI `content://` e concessão temporária de leitura. Se `canRequestPackageInstalls()` for falso, explicar em português e encaminhar às configurações de fontes desconhecidas; reavaliar ao retornar.
- Tratar cancelamento, erro HTTP/autorização, falta de espaço, conflito de nome e ausência de notificação concedida sem expor URL assinada ou credenciais.

Exclusões: atualização automática/silenciosa, instalação automática, APK dividido e instalação em lote. Um SHA-256 compara o arquivo com a fonte publicada; não comprova autoria quando a mesma fonte controla APK e checksum. A distribuição oficial documentada é GitHub Releases; este fluxo não publica no Google Play.

## Pré-condições e decisões

- C21.1 DONE. Decisão do usuário: download e instalação manual de APKs das próprias releases.
- Repositório, asset e token vêm da sessão/release selecionada. O token de acesso fica apenas em `SecureSessionStore`; os metadados persistidos pelo worker contêm owner, repo, IDs, nome e URI de destino.
- WorkManager foreground usa tipo `dataSync` para `targetSdk 36`; Android 16+ pode aplicar cota de `JobScheduler`, limitação a validar no aparelho. Não há fallback silencioso para `DownloadManager`, pois ele reaplica headers customizados em redirects no AOSP consultado.
- API 26–28 exige escolha de destino pelo seletor SAF; API 29+ grava diretamente em Downloads via MediaStore. Se o usuário cancelar o seletor, nenhum worker é iniciado.
- Para release privada, o token precisa ter permissão GitHub `Contents: read`. Erro de autorização não inicia fluxo de instalação.

## Aceite

1. **Dado** um asset APK, **quando** toco “Baixar”, **então** um único download identificável aparece com bytes/progresso (indeterminado se o total for desconhecido), ação de cancelar e notificação de andamento; ao concluir, o arquivo aparece no destino permitido e o estado fica disponível ao reabrir Releases.
2. **Dado** um APK com `digest` SHA-256 da API ou entrada correspondente em `SHA256SUMS`, **quando** termina o streaming, **então** o app mostra a origem e o resultado da comparação; divergência apaga o arquivo e impede “Instalar”. Sem hash publicado, o app informa “Não verificado”.
3. **Dado** um APK concluído e sem divergência, **quando** toco “Instalar”, **então** o instalador do Android abre por URI `content://`; se a permissão desta fonte estiver desativada, o app explica a ação, abre as configurações e reavalia ao retornar.
4. **Dado** repositório privado, **quando** a API responde `200`, o corpo binário é salvo; **quando** responde `302`, somente a URL HTTPS redirecionada é buscada sem `Authorization`. Nenhuma credencial ou URL assinada aparece em saída persistida.
5. **Dado** cancelamento, erro HTTP, falha de escrita/sem espaço, nome existente ou permissão de notificações negada, **então** o app limpa staging/registro pendente quando possível, preserva arquivos já publicados do usuário e apresenta estado recuperável em português.

## Verificação

- Testes unitários: seleção e comparação de checksum; endpoint/header/redirect; garantir ausência de bearer no segundo host; streaming direto `200`, redirect `302`, cancelamento e estados de erro.
- Testes instrumentados: navegação Releases → baixar → estado/progresso → instalar/permissão. Não usar conta nem token real em fixture.
- Compilar e executar `./gradlew assembleDebug testDebugUnitTest lintDebug`; executar `./gradlew connectedDebugAndroidTest` com emulador ativo conforme AGENTS.
- Procedimento manual em Android real: confirmar download público e privado com sessão de teste, cancelamento, permissão de notificação, checksum correspondente/divergente e abertura do instalador. Não confirmar instalação concluída sem resultado observado no dispositivo.
- Pesquisa oficial e decisões técnicas: `docs/research/C21.2-android-download-install.md`; referências primárias Android e GitHub registradas no documento.
