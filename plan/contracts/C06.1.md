# C06.1 — Detalhe real do repositório e README

## Escopo

Ao tocar um repositório real na aba **Repos**, abrir detalhe vinculado ao
identificador selecionado e carregar os metadados atuais de
`GET /repos/{owner}/{repo}` e o README de
`GET /repos/{owner}/{repo}/readme?ref={default_branch}`. Exibir proprietário,
nome completo, descrição, visibilidade, branch padrão, estrelas, forks, total
aberto de issues **mais** pull requests (`open_issues_count`) e data/hora do
último push (`pushed_at`). Os valores vêm da resposta atual da API. Campo
numérico ausente/null aparece como indisponível, nunca como zero; zero explícito
continua sendo um valor válido.

O README será decodificado do conteúdo Base64 da resposta e exibido em área
rolável como texto Markdown inerte: headings, delimitadores, links e blocos de
código não executam HTML, JavaScript, imagens, comandos ou navegação nesta
entrega. README ausente é um estado informativo próprio, distinto de falha.
Atualizar repete a consulta de metadados e README; retornar volta à mesma lista.

Fora do escopo: painel da conta (C06.2), lista de commits/eventos, separar
contagens de issues e PRs, trocar branch, editar repositório, abrir links/imagens
do README, cache offline e reautorizar ou ampliar escopos OAuth. A atividade
resumida nesta tela significa somente `pushed_at`; não é histórico de commits.

## Pré-condições e decisões

- C05.1 fornece os repositórios reais, owner, nome e id; C05.2 mantém busca e
  filtros locais na lista. A seleção não pode abrir o detalhe de linhas de
  demonstração nem perder a identidade do item.
- Usar os endpoints oficiais **Get a repository** (permissão Metadata: read para
  fine-grained tokens) e **Get a repository README** (Contents: read para
  fine-grained tokens). O OAuth App já solicita `repo`; não alterar escopos.
- A rota é construída com owner e nome da resposta já validada, codificados por
  segmento; não aceitar URL arbitrária nem transmitir credenciais fora de
  `api.github.com`.
- Campos de contagem consumidos: `stargazers_count`, `forks_count` e
  `open_issues_count`. O último agrega issues e pull requests abertos e deve ser
  rotulado dessa forma. `watchers_count` não será rotulado como watchers, pois a
  API o mantém equivalente a estrelas.
- Branch padrão vem de `default_branch`; visibilidade de `visibility` ou do
  booleano `private`; atividade resumida vem de `pushed_at`. Campo inválido não
  deve produzir dado inventado ou zerado.
- README usa `content`/`encoding` da resposta JSON; só aceitar `base64`, decodificar
  UTF-8 e tratar conteúdo inválido com mensagem segura. Um `404` do README mostra
  “README não encontrado”; um `404` dos metadados mantém o significado de
  repositório indisponível. `401` encerra a sessão conforme C05.1, `403` informa
  permissão insuficiente e erros transitórios permitem tentar novamente.
- A atualização refaz as duas consultas de forma explícita e refletirá valores
  alterados no GitHub. Não atualizar automaticamente em loop.

Fontes oficiais atuais: [Get a repository](https://docs.github.com/en/rest/repos/repos#get-a-repository),
[Get a repository README](https://docs.github.com/en/rest/repos/contents#get-a-repository-readme)
e [OAuth App scopes](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/scopes-for-oauth-apps).

## Aceite

1. Dada uma lista real carregada e sessão válida, quando a pessoa toca numa linha,
   então o detalhe solicita os metadados do mesmo owner/repo e mostra identidade,
   visibilidade, branch padrão, descrição e contagens com os rótulos definidos;
   não mostra dados da demonstração.
2. Dada uma resposta com contagem explícita zero, quando o detalhe é exibido,
   então mostra zero; se um campo numérico esperado estiver ausente/null, então
   mostra indisponível e não converte falta de dado em zero.
3. Dado `pushed_at` válido, quando o detalhe é exibido, então mostra a data/hora
   de último push identificada como atividade recente; valor ausente/inválido
   mostra indisponível, sem inferir “hoje”.
4. Dado README Base64 válido, quando a consulta termina, então o conteúdo
   decodificado aparece em área rolável como texto inerte; tags, scripts, links,
   imagens e blocos de código não são executados nem abertos.
5. Dado README inexistente (`404`), quando os metadados existem, então o restante
   do detalhe continua disponível e a área informa que não há README; falha no
   endpoint de metadados não é apresentada como README vazio.
6. Dado detalhe aberto, quando a pessoa atualiza, então metadados e README são
   carregados novamente sem duplicar tela/itens; ao voltar, a lista real conserva
   os filtros locais C05.2.
7. Dada falha de autenticação, permissão, rede ou rate limit, quando a consulta
   falha, então a interface usa o tratamento C05.1 aplicável, permite retry
   explícito para falhas transitórias e não registra token nem conteúdo privado.
