# C07.1 — Lista e filtros de issues

## Escopo

Na aba Trabalho autenticada, trocar o placeholder por uma lista paginada de issues reais visíveis à conta. Incluir os escopos “Atribuídas a mim”, “Criadas por mim” e “Todas visíveis”, além de estado Aberta, Fechada ou Todas. Buscar no endpoint autenticado `GET /issues` com os parâmetros `filter`, `state`, `pulls=false` e `per_page=50`; carregar a próxima página somente por ação explícita e pelo link `rel="next"` validado no cliente HTTP. O padrão inicial é “Atribuídas a mim” e “Abertas”.

Cada item mostra título, número, repositório, estado, autor, responsáveis, labels e data de atualização quando válidos. Excluir todo resultado com `pull_request`, inclusive quando a API o incluir, e deduplicar por repositório e número. Conteúdo de issues permanece texto inerte; a descrição Markdown, comentários e tela de detalhe ficam para C07.2. Sem sessão, manter instrução de conexão; nunca usar DemoData como issue real.

Fora do escopo: busca textual, seleção de repositório, detalhe, descrição Markdown, comentários, edição, criação, notificações, cache e filtros por terceiros. Exibir erro de permissão como recurso indisponível e permitir retry explícito; não reautorizar escopos automaticamente.

## Pré-condições e decisões

- C06.1 concluída; a sessão fornece token em memória e login autenticado. O escopo OAuth atual contém `repo`, necessário para recursos privados que a conta pode acessar.
- A listagem agregada de issues autenticadas oferece filtros `assigned`, `created` e `all`; estado aceita `open`, `closed` ou `all`. `pulls=false` e a verificação local de `pull_request` protegem a distinção issue/PR. O endpoint pode incluir itens de repositórios públicos, próprios, membros ou organizações conforme acesso e escopo.
- `GET /issues` é consultado página a página. Seguir apenas URL `rel="next"` da resposta depois de validação de origem por `GitHubHttpClient`; botão “Carregar mais” fica oculto sem próxima página e desabilitado durante consulta.
- Campo ausente/opcional de autor, responsável, labels ou atualização usa texto de indisponibilidade; número, estado, título, URL e repositório inválidos tornam o item malformado e ele é descartado sem log dos dados. Um array vazio válido é estado vazio, nunca erro.
- `401` expira a sessão uma vez; `403`, rate limit, rede, `5xx` e JSON inválido mostram estado específico e retry. Preservar itens já carregados somente quando seguro e identificá-los como resultados anteriores durante falha de paginação. Não registrar token, payloads, logins reais ou títulos reais em evidências.

Fontes oficiais: [REST API — issues, filtros e paginação](https://docs.github.com/en/rest/issues/issues) e [Paginação REST](https://docs.github.com/en/rest/using-the-rest-api/using-pagination-in-the-rest-api).

## Aceite

1. Dada uma sessão válida, quando Trabalho abre, então requisita `GET /issues` com filtros iniciais `assigned`, `open`, `pulls=false`, `per_page=50` e mostra apenas issues que passam pela validação de identidade, repositório e estado.
2. Dada seleção de escopo atribuídas/criadas/todas visíveis ou estado aberta/fechada/todas, quando muda o filtro, então reinicia a consulta desde a primeira página com os valores de query correspondentes e não mistura resultados de filtros anteriores.
3. Dado resultado com uma issue e um item que contenha `pull_request`, quando mapeado, então apenas a issue é exibida; itens duplicados entre páginas aparecem uma vez por repositório+número.
4. Dado um link `rel="next"`, quando a pessoa toca “Carregar mais”, então a próxima página é buscada uma única vez por URL validada e os itens válidos são anexados. Sem link seguinte, controles de continuação não aparecem. Refresh reinicia filtros atuais e paginação.
5. Dado resultado vazio, quando a página termina sem issues, então a tela informa que não há issues para os filtros escolhidos e mantém os filtros ajustáveis.
6. Dada ausência de sessão, quando Trabalho abre, então oferece conexão e nenhum item fictício. Dada resposta `401`, quando a carga falha, então solicita expiração da sessão uma vez. Para `403`, 429, rede, `5xx` e JSON inválido, então mostra o estado apropriado e retry explícito sem duplicar chamadas.
7. Dado título, autor ou repositório real na interface, quando testado por fixture ou fluxo manual, então nenhum campo pessoal real é salvo em logs, screenshot versionado ou evidência.
