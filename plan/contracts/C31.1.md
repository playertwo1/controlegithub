# C31.1 — Controle de imagens em Markdown / Economia de dados (OH-09)

## Escopo

- Criar `GitHubMarkdownImageLoader.kt` para download sob demanda de imagens referenciadas em Markdown:
  - Aceitar exclusivamente URLs `https://` válidas.
  - Nunca enviar cabeçalho `Authorization` / token OAuth para hosts de imagem.
  - Limitar o download a no máximo **5 MB** (`MAX_MARKDOWN_IMAGE_BYTES = 5 * 1024 * 1024`) com timeouts de conexão/leitura e decodificação segura em `Bitmap`.
- Atualizar `GitHubMarkdownContent.kt` para que, ao tocar em uma referência de imagem (`"Imagem: <alt>"`), o diálogo de confirmação `"Abrir link externo?"` preserve os elementos existentes (host, URL, `"Abrir no navegador"` e `"Cancelar"`) e ofereça também o botão **"Carregar imagem no app"** (`load_markdown_image_button`), exibindo a imagem carregada sob demanda ou erro explícito em português.
- Fora de escopo: download automático de imagens ao abrir Markdown ou tocar em `C21.3`.

## Pré-condições e decisões

- `C22.1` está `DONE`.
- Implementa `OH-09 — Controle de imagens em Markdown / Economia de dados`:
  - Zero requisições de imagem ocorrem automaticamente ao renderizar um Markdown.
  - Preserva 100% da compatibilidade com o fluxo de segurança de links externos de `C22.1` (`"Abrir link externo?"`).

## Aceite

1. Dado um documento Markdown contendo `![logo](https://example.test/logo.png)`, quando ele é renderizado em `GitHubMarkdownContent`, nenhuma requisição de rede é feita automaticamente para `example.test`.
2. Quando o usuário toca em `"Imagem: logo"`, o diálogo `"Abrir link externo?"` é exibido contendo o host `example.test`, a opção `"Abrir no navegador"`, `"Cancelar"` e a opção **"Carregar imagem no app"** (`load_markdown_image_button`).
3. Quando o usuário toca em **"Carregar imagem no app"**, o app baixa a imagem via HTTPS sem enviar credenciais OAuth, valida o limite de 5 MB e exibe a imagem decodificada (ou mensagem de erro clara se falhar/exceder o limite).
