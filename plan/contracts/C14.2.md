# C14.2 — Kanban local de issues

## Escopo

Implementar o quadro Kanban local de issues na aba Trabalho (`GitHubIssuesScreen.kt`), permitindo organizar as issues do usuário em quatro colunas de fluxo de trabalho:
- "A fazer" (`TODO`)
- "Em andamento" (`IN_PROGRESS`)
- "Em revisão" (`IN_REVIEW`)
- "Concluído" (`DONE`)

Comportamentos incluídos:
- Alternador de visualização na tela de Trabalho permitindo alternar entre "Issues" (lista), "Pull requests" e "Quadro" (Kanban).
- Renderização do quadro Kanban com as 4 colunas acessíveis com navegação horizontal/vertical.
- Cada cartão exibe repositório, número (#), título, rótulos e autor da issue real.
- Notificação/banner explicativo na UI deixando explícito que a organização é estritamente local ao dispositivo e não altera o estado da issue no GitHub.
- Mecanismo acessível de movimentação de cartões entre colunas através de ação "Mover" / folha modal "Mover cartão" com opções acessíveis sem depender exclusivamente de gesto de arrastar.
- Persistência das colunas das issues por conta no `Preferences DataStore` (`app_preferences`), restaurando o posicionamento após reinício do app/activity.
- Isolamento estrito por conta e limpeza dos dados do quadro ao realizar logout.
- Resiliência: issues que deixarem de existir ou não estiverem carregadas não quebram o quadro.
- Garantia de mutação zero no GitHub: mover colunas não dispara nenhuma requisição HTTP à API do GitHub.

Exclusões deste contrato:
- Integração com GitHub Projects (v2) ou campos de projetos no GitHub (o quadro é local).
- Arraste com animação física complexa baseado em bibliotecas externas (usar componentes nativos Compose com alternador acessível).
- Criação de novas colunas customizadas pelo usuário (as 4 colunas são fixas e atendem ao ROADMAP).

## Pré-condições e decisões

- Pré-requisitos C07.2 (Detalhe e conversa da issue) e C11.2 (Refresh e reconexão) concluídos com sucesso (`DONE`).
- Decisão sobre persistência (`KanbanStore.kt`):
  - Utiliza o `preferencesDataStore` da aplicação já empregado para tema e favoritos de repositórios.
  - Chave de preferências: `kanban_issue_columns_${accountLogin.lowercase(Locale.ROOT)}`.
  - Mapeia `issueIdentity` (`owner/repo/number`) para `KanbanColumn`.
  - Regra padrão para issues sem coluna definida:
    - Se a issue estiver fechada no GitHub (`GitHubIssueState.CLOSED`), coluna inicial é "Concluído".
    - Se a issue estiver aberta no GitHub (`GitHubIssueState.OPEN`), coluna inicial é "A fazer".
- Decisão sobre UI:
  - Selector no topo da tela Trabalho inclui chip "Quadro".
  - Banner visível: "Organização local: mover os cartões organiza seu trabalho neste aparelho e não altera o estado da issue no GitHub."
  - Botão de mover no cartão abre seletor acessível da coluna de destino.
  - Toque no cartão navega para o detalhe da issue (`GitHubIssueDetailScreen`).

## Aceite

1. **KANBAN-VIEW (Exibição do quadro e aviso local):**
   **Dado** um usuário autenticado na aba Trabalho,
   **quando** seleciona a visualização "Quadro",
   **então** as 4 colunas ("A fazer", "Em andamento", "Em revisão", "Concluído") são exibidas e o banner informativo explicita que mover cartões não altera o GitHub.

2. **KANBAN-MOVE (Movimentação de cartão entre colunas):**
   **Dado** uma issue exibida na coluna "A fazer",
   **quando** o usuário aciona a ação de mover e seleciona "Em andamento",
   **então** o cartão é transferido imediatamente para a coluna "Em andamento" sem nenhuma chamada HTTP de escrita ou alteração no GitHub.

3. **KANBAN-PERSIST (Persistência após reinício):**
   **Dado** que o usuário moveu issues para diferentes colunas,
   **quando** a Activity ou o aplicativo reinicia,
   **então** os cartões reaparecem nas colunas previamente definidas.

4. **KANBAN-ACCOUNT-ISOLATION (Isolamento por conta e limpeza no logout):**
   **Dado** um usuário com issues organizadas no quadro,
   **quando** efetua logout,
   **então** as posições de Kanban dessa conta são removidas do DataStore, impedindo que outra conta veja seus cartões.

5. **KANBAN-MISSING-ITEM (Resiliência a itens ausentes):**
   **Dado** registros de coluna salvos para uma issue que não consta mais na lista carregada,
   **quando** o quadro é renderizado,
   **então** o aplicativo não trava, ignora com segurança o item ausente e renderiza os itens válidos.
