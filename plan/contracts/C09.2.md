# C09.2 — Marcar notificações lidas

## Escopo

Permitir que o usuário marque uma notificação como lida no GitHub a partir da tela de detalhes da notificação, enviando requisição `PATCH /notifications/threads/{thread_id}` autenticada.
A confirmação só atualiza o estado local para "Lida" após resposta bem-sucedida do GitHub (`205 Reset Content` ou `304 Not Modified`).
Em caso de erro (rede, timeout, 401, 403, 404, 429 ou erro do servidor), a notificação permanece "Não lida" e uma mensagem de erro clara é exibida ao usuário, permitindo nova tentativa.
Toques repetidos durante a chamada em andamento são ignorados para evitar duplicidade de requisições.
Exclusões: marcar todas como lidas em lote (`PUT /notifications`), alterar subscrições (watch/ignore/subscribe), fila de sincronização offline ou reenvio automático em segundo plano.

## Pré-condições e decisões

- C09.1 está concluído (`DONE`), garantindo a listagem, paginação, filtros e navegação segura para os destinos de notificação com token OAuth Device Flow clássico (escopos `repo` e `notifications`).
- Endpoint oficial do GitHub REST: `PATCH /notifications/threads/{thread_id}`.
- Respostas esperadas da API: `205 Reset Content` (marcada com sucesso) e `304 Not Modified` (já estava lida no servidor). Ambas indicam que a thread está lida.
- Decisão sobre escrita real: conforme regra do projeto, a implementação é testada primeiro de forma determinística com fixtures locais. Qualquer mutação real no GitHub exige autorização humana explícita do alvo (identificador da thread e repositório) nesta sessão antes da execução.
- `GitHubHttpClient` deve suportar o método `PATCH` com corpo vazio (`Content-Length: 0`), tratando `205` e `304` como sucesso sem exigir payload JSON de resposta.

## Aceite

1. **Dado** uma notificação não lida selecionada, **quando** o usuário aciona "Marcar como lida" e o GitHub responde `205 Reset Content` ou `304 Not Modified`, **então** o estado da notificação muda para "Lida" tanto no detalhe quanto na lista de avisos, e o botão de marcar como lida é desabilitado/ocultado.
2. **Dado** uma solicitação de marcar como lida em andamento, **quando** o usuário tenta novo toque repetido antes da resposta, **então** a ação repetida é bloqueada e nenhuma requisição duplicada é enviada.
3. **Dado** uma tentativa de marcar como lida, **quando** a conexão falha por timeout, erro de rede, `403 Forbidden`, `404 Not Found` ou `500 Server Error`, **então** a notificação permanece como "Não lida", o estado de erro específico é exibido ao usuário e o botão permite nova tentativa.
4. **Dado** que a sessão expirou (`401 Unauthorized`), **quando** o usuário aciona marcar como lida, **então** a falha de autenticação é tratada pelo ciclo de sessão sem marcar a notificação como lida localmente.
5. **Dado** o filtro "Não lidas" ativo na caixa de avisos, **quando** uma notificação é marcada como lida com sucesso e o usuário volta à lista, **então** o item deixa de constar na lista filtrada sem perda de integridade da paginação.
