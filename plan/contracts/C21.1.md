# C21.1 — Releases do repositório

## Escopo

Nova aba/seção "Releases" no detalhe do repositório (M5, v2.0):
- Listar releases reais via `GET /repos/{owner}/{repo}/releases` com paginação (reuso de C04.2).
- Mostrar nome, tag, data, autor, selos "Pré-release"/"Rascunho" e "Mais recente".
- Detalhe da release: notas (texto; Markdown fica para OH-03) e lista de assets com nome, tamanho, contagem de downloads e tipo.
- Destacar assets `.apk` e o `SHA256SUMS.txt` quando existirem.
- Estados: carregando, vazio ("Nenhuma release publicada"), erro com tentar de novo, offline com cache (C11).

- Saúde dos repositórios (pedido do usuário): status Ativo (≤30 dias), Pouco movimento (≤90), Parado (≤365), Abandonado (>365) ou Arquivado, com dias sem push, na lista e no detalhe.
- Interino até C21.2: "Baixar" abre o link oficial do asset (`https://github.com/...`) no navegador.

Exclusões: download e instalação (C21.2); criar/editar releases.

## Pré-condições e decisões

- C20.2 DONE. Endpoint público de releases; mesmo token OAuth da sessão.

## Aceite

1. **Dado** um repositório com releases, **quando** abro "Releases", **então** vejo a lista real ordenada da mais nova para a mais antiga.
2. **Dado** uma release, **quando** abro o detalhe, **então** vejo notas e assets com tamanho legível; APKs aparecem destacados.
3. **Dado** um repositório sem releases ou falha de rede, **então** vejo estado vazio ou erro, nunca dados de demonstração.
