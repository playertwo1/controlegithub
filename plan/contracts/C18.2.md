# C18.2 — Release assinada e atualização

## Escopo

Estabelecer a infraestrutura de compilação, assinatura segura e atualização da versão 1.0 do aplicativo ControleGitHub:
- Configuração de build release no Gradle (`app/build.gradle.kts`):
  - Suporte a `signingConfigs.release` parametrizável via variáveis de ambiente ou propriedades locais (`RELEASE_STORE_FILE`, `RELEASE_STORE_PASSWORD`, `RELEASE_KEY_ALIAS`, `RELEASE_KEY_PASSWORD`).
  - Fallback controlado para assinatura de desenvolvimento/CI quando as credenciais de produção não forem fornecidas.
  - Incremento de versionamento formal para a versão de lançamento: `versionCode = 100`, `versionName = "1.0.0"`.
- Proteção estrita de segredos de assinatura:
  - Garantia de que nenhum arquivo de keystore privado (`*.keystore`, `*.jks`) ou senha de release seja versionado no repositório Git (`.gitignore` auditado).
- Integridade na atualização de versão:
  - Verificação de que a instalação de atualização do APK assinado sobre uma instalação existente preserva o sandbox do aplicativo, incluindo credenciais no `AndroidKeyStore`, banco SQLite do cache e preferências no DataStore, sem reset ou perda de dados.
- Documentação do canal de release (`docs/RELEASE.md`):
  - Procedimento padronizado de compilação da release (`./gradlew assembleRelease`).
  - Cálculo e validação do checksum SHA-256 do artefato gerado.
  - Especificação do canal oficial de distribuição (GitHub Releases) e notas de atualização para os usuários.

Exclusões deste contrato:
- Publicação automatizada na Google Play Console (escopo de C20.2 / pós-1.0).

## Pré-condições e decisões

- Checkpoint C18.1 concluído com sucesso (`DONE`).
- Decisão sobre chaves de assinatura: chaves de produção geradas fora do repositório; para testes locais e CI, é gerada uma chave de release local efêmera ignorada no `.gitignore`.
- Decisão sobre canal de distribuição: o canal primário da versão 1.0 é o GitHub Releases com artefato APK standalone assinado e acompanhado de checksum SHA-256.

## Aceite

1. **RELEASE-SIGNING-CONFIG (Configuração segura de assinatura):**
   **Dado** a execução da tarefa `:app:assembleRelease`,
   **quando** o comando Gradle é disparado,
   **então** o artefato release é gerado e assinado com alinhamento (`zipalign`) e assinatura v2/v3, lendo credenciais de forma segura sem expor senhas no código versionado.

2. **RELEASE-UPGRADE-PRESERVES-DATA (Preservação de dados em atualização):**
   **Dado** uma instalação prévia do aplicativo contendo sessão, cache e preferências,
   **quando** uma nova versão assinada com a mesma chave é instalada em substituição (`adb install -r`),
   **então** os dados locais (banco SQLite de cache, preferências de tema/sincronização e credenciais criptografadas) permanecem intactos e acessíveis sem falhas ou corrupção.

3. **RELEASE-DISTRIBUTION-CHANNEL (Documentação e verificação do canal):**
   **Dado** o arquivo `docs/RELEASE.md` na documentação do projeto,
   **quando** consultado por desenvolvedores ou usuários,
   **então** o documento descreve os passos exatos de compilação da release, conferência de integridade por hash SHA-256, publicação no GitHub Releases e instruções de atualização.
